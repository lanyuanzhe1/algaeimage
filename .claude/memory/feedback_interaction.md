**规则**:
- 能用并行 agent 解决的任务，优先并行而非串行
- 优先用 Bash 直接执行命令而非交互式确认（如 `rm`、`git reset` 等破坏性操作仍需确认）
- 当有新工具/新概念出现时，先解释原理再操作（用户偏好学习底层机制）
- 知识笔记写出后应继续追问深度原理，不满足于表面解释

**Why**: 
- 用户频繁使用并行 agent 处理多文件任务，串行效率太低
- 用户说过"解释原理"多次——不理解原理就无法自己维护
- 用户主动建立了知识笔记本系统，需要深度内容填充

**How to apply**: 任务天然可分时主动提出并行方案。使用新工具前先解释它的工作原理。用户追问"原理"时深入到底层机制。
